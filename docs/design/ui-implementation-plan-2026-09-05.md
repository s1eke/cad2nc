# CAD2NC UI 重设计实施规划

日期：2026-09-05。状态：2.5.0 界面重设计已实施并发布；本机 C#、UIA、输出一致性与打包检查通过，物理输入和未覆盖系统环境见验证记录。

设计依据：[工作台重设计提案](ui-redesign-2026-09-05.md)及[概念图](ui-redesign-2026-09-05.png)。实现采用现有 WinUI 3 / Win2D，已包含紧凑顶部、工艺分组、轮廓缩略图与加工侧详情、旧刀路失效提示、中央结果抽屉与大视图、NC 源码并排阅读和独立宽度偏好。

以下阶段、完成标准与验收矩阵保留为实施依据，不能视为全部已通过。最终实测结果、发布产物以及未覆盖环境以 [验证记录](../VALIDATION.md) 为准，历史验收记录不作为本次结果。

已完成的输出对比：`build/ui-redesign-baseline` 中 clean 与 real 两组 before／after JSON 均只有输出文件路径和应用版本（2.4.0 → 2.5.0）变化；轮廓、加工侧、原点、刀路统计及读取提示逐项相同，两组 NC 文件均字节一致。该对比仅证明这两份输入在本次参数下的输出一致，不代替完整 UI、DPI、安装与机床验证。

## 一、实施目标与已确定的取舍

1. 采用紧凑顶部、轮廓列表、大画布、工艺面板及中央结果抽屉的布局。浅色／深色／跟随系统继续支持，画布保持深色。
2. 生成、导出按钮位置固定；由现有 WorkbenchUiState 决定强调、标签和可用状态。保留底层保存行为，界面将“保存 NC”统一命名为“导出 NC”，相关提示和自动化断言同步更新。
3. 按原生控件实现效果图：文字、表单、图标用 WinUI，刀路及技术示意使用已有几何和绘图能力。示例图形、尺寸、时长不能作为实际应用数据。
4. 此轮重点改进展示与操作组织，沿用现有 CAD 导入、刀路规划、补偿、原点、NC 生成和任务存储语义。新 UI 中出现的层数、顺序、尺寸、时间均来自相应真实数据。
5. 首次使用的侧栏默认宽度为左 240、右 320 DIP；已保存的合法用户宽度继续生效。保持现有 1200／900 DIP 响应式断点，按实际可用空间校正。
6. 画布 60% 是默认侧栏、大屏环境下的设计目标。1440 DIP 宽度应接近 60%；1366 DIP 下优先保持约 520 DIP 以上的可用画布及可读的参数；不对所有窗口强制百分比。
7. “加工顺序”首轮是查看有效刀路顺序的视图，不增加手动拖拽排序或改动孔优先算法。参数变更明细和复杂局部补偿比较作为后续增强。

## 二、实施前基线

- 保存同一真实图纸、同一参数在明暗主题与不同窗口宽度下的现有截图，涵盖空任务、已导入、已生成、待更新、诊断、NC 阅读。
- 使用独立 QA 目录放置图纸副本、设置、加工任务和输出，沿用 CAD2NC_SETTINGS_DIRECTORY 隔离能力。
- 复用当前已有构建／测试工具，记录此次实际运行结果。docs/VALIDATION.md 中的 335 项测试与历史截图是参考基线，不冒充本次执行证据。
- 实施产物先放到独立预览目录，例如 build/preview-ui-redesign；正式安装包放在集成验收之后处理。

## 三、阶段与完成标准

### 阶段 1：统一画布结果状态与刷新

目标：首先让当前参数、画布和主操作表达同一结果状态。

工作项：

- 从会话状态推导画布的当前结果／上次结果／无结果展示，不在界面复制一套导出资格规则。
- 失效刀路、成品边及其方向标记降亮；就近显示“上次结果 · 待更新”。原图和当前轮廓选中状态继续保持清晰。
- 将失效状态独立传递给 CadCanvas，并在状态变化时标记静态绘图缓存需要刷新。必须在 BuildScene 的引用相等提前返回之前更新展示状态，或将其纳入缓存键。
- 重新生成成功后恢复正常样式；换图、打开 NC、取消、失败、撤销重做按现有会话语义清理或更新状态。

主要文件：MainWindow.xaml.cs、Controls/CadCanvas.cs；必要时扩展 Application/WorkbenchUiState.cs 的展示信息。

完成标准：修改进给这种不改变几何对象引用的参数，也能立即看到“待更新”；不依赖缩放或切换窗口触发重绘。旧结果仍不可导出、复制或播放。视图缩放、图层开关及面板调整不使任务变脏。

### 阶段 2：顶部与工作区骨架

目标：交付第一版新的整体布局。

工作项：

- 合并文件信息和主命令区域，增加简短状态行；正常状态顶部目标总高约 88–96 DIP，临时通知额外占位。
- 独立处理窗口拖动区域和按钮命中区域，保留系统窗口控制与快捷键；长文件名省略并可查看完整路径。
- 在 App.xaml 集中定义间距、控件高度、分隔线、文本层级、主题及画布颜色资源，减少嵌套卡片边框。
- 将画布、播放、结果标签条与结果内容组织为中央容器；左右侧栏保持全高。结果展开、收起和调整高度仅改变中央区域。
- 更新 ApplyView、结果拖动比例的参考容器与初次适应全图逻辑。保留 900–1199 DIP 的画布加单侧栏，以及低于 900 DIP 的四视图切换。
- 窄屏将次要命令放入更多菜单，主操作仍可达；“打开 NC”的阅读布局在阶段 5 完善。

主要文件：MainWindow.xaml、MainWindow.xaml.cs、MainWindow.Workflow.cs、App.xaml、Application/Persistence.cs。

完成标准：1366×768 DIP 下主要操作可用，侧栏表单可滚动；展开诊断不减少左右面板高度；结果区在保留的 22%／55% 拖动边界均正确显示。切换明暗主题、拖动侧栏、跨响应式断点再返回都保持一致布局。真实指针点击和菜单展开正常，窗口可拖动，双击最大化和系统窗口控件正常；不能只用 UIA Invoke 代替命中测试。

### 阶段 3：工艺参数重组

目标：同屏读取常用工艺，减少滚动，并保留完整输入能力。

工作项：

- 分成“刀具”“切削”“深度与分层”“补偿与方向”。刀号／H／刀径就近放置；转速／进给及目标 Z／安全 Z 可在宽度足够时双列。
- 保留刀具名称、主轴旋向、几何走刀方向、封边吃料、下刀进给、最大单层下切及 H 跟随刀号等全部现有字段。
- 保留 NumberBox 的解析、非法输入、键盘和滚动能力；单位作为输入框旁固定元素，不混入数值字符串。
- 使用一份明确的“字段 → 分组 → 控件”映射，供错误定位和说明页返回修改共用。消除 LocateGuideField 对 ParameterPanel 直接子级 Expander 的结构依赖。
- 深度分组显示真实预计层数和最终 Z，并添加标明“示意”的高度小图；不以图中比例暗示真实空间关系。

主要文件：MainWindow.xaml、MainWindow.xaml.cs、MainWindow.Configurations.cs、MainWindow.Workflow.cs、App.xaml。

完成标准：每个字段的输入错误都能展开正确分组并定位；在窄屏从说明页返回也能看到目标字段。T／H 独立修改、跟随、撤销重做、配置导入、恢复默认和任务恢复行为与现有一致。

阶段 1–3 构成第一轮可运行预览，覆盖最主要的状态、空间和表单问题。

### 阶段 4：轮廓列表、加工侧与画布图例

目标：快速对应图形，清楚区分查看对象和加工对象。

工作项：

- 从真实轮廓生成等比例缩略图，按文档身份与轮廓几何缓存；小图使用轻量路径绘制，保留 ListView 虚拟化，避免每行创建独立 Win2D 画布。
- 当前选中使用行底色／边线，参与加工使用复选框；持续显示选中数和加工数。
- 保留搜索和 CAD 图层过滤；批量菜单明确显示作用集合及数量，无选中项时禁用选中项操作。
- 行内显示简短加工侧；单选显示内／外侧示意，多选显示共同值或“混合”，批量应用仍调用现有会话操作。
- 增加“全部／加工顺序”查看切换。只有有效计划显示有效顺序；计划失效时明确提示需更新，不把上次顺序当成当前结果。
- 将原图、成品边、刀心、空移和方向图例放入画布边缘，直接绑定现有五类显示状态；不遮挡主要绘图区。

主要文件：MainWindow.xaml、MainWindow.xaml.cs、Controls 新增轻量缩略图／加工侧示意控件、CadCanvas.cs。

完成标准：搜索、多选、勾选、批量修改和画布定位一致；切换图纸后不会沿用同编号旧缩略图。对多轮廓图纸检查滚动和缩放，缩略图不在每次播放帧中重新计算；大坐标和细长轮廓保持比例。

### 阶段 5：NC 阅读与结果大视图

目标：同时核对源码、参数和二维轨迹。

工作项：

- CAD 模式下，中央结果标签提供加工摘要／NC 代码／诊断；长源码或诊断提供可返回的大视图。
- 外部 NC 在宽屏提供画布与程序详情并排，详情切换源码／程序参数／解析提示；不显示可编辑加工参数。
- 根据可用宽度降级为单区域阅读，低于 900 DIP 延续预览／程序详情切换。无法绘制的程序优先展示源码与解析提示。
- 整理可复用的程序详情视图，复用现有 NC 行数据及播放控制器；避免两个视图各自维护播放位置，或把同一 XAML 控件同时挂载到不同父级。
- 继续使用现有代码行点击定位、播放行高亮、XYZ、倍率和暂停行为。带来源行的解析提示提供跳转；无来源行时不伪造定位。
- NC 专用面板尺寸保存在本机展示设置，不能覆盖 CAD 侧栏偏好或加工参数。新设置有缺省值，旧任务和旧设置可正常打开。

主要文件：MainWindow.xaml、MainWindow.Workflow.cs、MainWindow.Playback.cs、MainWindow.xaml.cs；需要新布局偏好时修改 Application/Persistence.cs。

完成标准：可播放 NC 的行、轨迹和坐标同步；不支持的程序可读原文但不能播放。CAD → NC → CAD 不串用参数、选择、播放或布局状态；没有声明的程序参数仍显示“未提供”。

### 阶段 6：集成与验收

目标：交付可运行预览、真实截图和明确的验证记录。

- 每阶段完成有针对性的编译与行为检查；集成后运行完整 C# Release 回归，记录新增／原有测试的实际结果。
- 更新现有 UIA 脚本中的布局假设、分组和文案定位；优先保留既有 AutomationId。补充测试验证新的行为契约，不为装饰颜色或与实现逐字对应的结构添加单元测试。
- 运行 test_header_layout.ps1、test_workbench_v23.ps1、test_workbench_playback.ps1、test_workbench_storage.ps1，明确指向本次预览构建。
- 使用真实 DWG、clean_mm.dxf 和 smoke_mm.dxf 验证导入／生成／导出；复核圆弧、螺旋、仅 Z 运动和不支持指令的 NC 阅读。
- 对同输入、同参数比较计划摘要和 NC 输出。只有界面变化时，几何、补偿、原点与 NC 内容应保持一致；差异必须解释并处理。
- 人工复核关键截图和键盘操作后，更新 docs/images、README 和 docs/VALIDATION.md；记录实测 DPI 和尚未覆盖的环境。

最终产物：新的自包含预览程序、明暗／宽窄工作台截图、NC 阅读截图、回归报告及更新后的使用说明。正式安装包以验证过的构建为基础生成，不覆盖旧验收记录。

## 四、必须覆盖的验收矩阵

| 维度 | 用例与检查点 |
| --- | --- |
| 窗口 | 1440×940、1366×768、1000×900、820×900 DIP；补充 899／900、1199／1200 断点往返和更窄窗口的命令可达性 |
| 缩放与主题 | 浅色、深色、跟随系统；实测 100%／125%／150%／200% DPI，不能用图片缩放代替系统 DPI 验证 |
| 任务阶段 | 空任务、导入中、未选中、输入错误、可生成、生成中、成功、Warning、Error、已失效、取消、重新生成 |
| 轮廓 | 母板候选、内／外侧、单选、多选、混合加工侧、筛选后批量操作、大坐标、多轮廓 |
| 参数 | 所有字段错误定位、说明返回修改、T／H、负 Z、分层、撤销重做、导入配置、恢复默认、重开任务 |
| 视图与数据 | 折叠、尺寸、图例、源码视图、主题操作不改变加工设置／输出资格／任务脏状态；旧设置可加载 |
| 播放 | 播放／暂停、定位后保持暂停、倍率、末尾重播、失效清理、NC 行高亮和 XYZ 一致 |
| 文件 | 直接保存、另存、覆盖／取消、原生选择器、打开失败保留原内容、拖放和窗口激活 |
| 可访问性 | Tab 顺序、键盘触发、焦点可见、控件名称、错误朗读及高对比度；颜色不是唯一状态编码 |

未能运行的环境或人工用例明确列为未验收，不影响已完成阶段的实际记录。

## 五、任务拆分与依赖

主顺序：基线 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4／5 → 阶段 6。

可并行准备的任务是视觉资源规范、缩略图／示意控件以及测试用例清单。MainWindow.xaml 和 ApplyView 的骨架改造由同一实施负责人集成；参数和 NC 布局在骨架接口稳定后接入，避免多人同时改同一个布局入口。

每阶段作为独立、可构建的改动批次，附对应截图和检查结果。出现问题时可定位到具体批次，不以一次大规模代码拆分作为 UI 改造的前置条件。

## 六、当前源码中需要同步修改的耦合

| 耦合 | 实施要求 |
| --- | --- |
| BuildScene 按 document／plan 引用和加工 ID 判断是否重建 | 将失效显示状态独立更新或纳入缓存判断，同时刷新 CadCanvas 的静态绘图缓存 |
| ApplyView 同时负责主题、断点、面板可见性、结果行高度及图例 | 中央结果结构变更必须同步修改布局计算、拖动比例与首次取景 |
| PresentFirstValidationError 使用硬编码字段分组；LocateGuideField 遍历直接子级 | 用统一字段定位映射替换对旧层级的依赖 |
| SetTitleBar 与交互命令进入同一顶部区域 | 检查拖动区域、按钮点击、系统窗口操作和长文件名布局 |
| 当前 UIA 依赖固定控件 ID、命令对齐与默认参数分组 | 保留 ID，更新已变更的布局契约；不能通过删除行为断言来让测试通过 |
| ViewState 保存侧栏宽度、活动面板和结果高度比例 | 保留合法旧偏好，新字段缺省可用，展示操作保持不改变任务数据 |
